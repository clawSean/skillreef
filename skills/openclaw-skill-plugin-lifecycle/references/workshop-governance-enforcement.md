# Workshop Governance Adapter Setup

Use this when an operator wants autonomous Skill Workshop reviews to receive
the same lifecycle and workspace-skill authority used by foreground authoring.

## Distribution and authority

- Plugin ID: `workshop-governance-context`
- Editable upstream:
  <https://github.com/EdgeClaws/openclaw-workshop-governance>
- Installable bundled copy: `../assets/workshop-governance-plugin/`
- Vendor receipt: `workshop-governance-plugin.lock.json`

The shared repository is the only editable plugin source. The copy inside this
skill is generated byte-for-byte from a clean upstream commit and locked by
commit plus tree checksum. Do not hand-edit the vendored copy.

The plugin loads the lifecycle skill and governance references from the active
agent's canonical workspace on every targeted review. It injects those files
and a compact workspace-skill inventory into detached experience reviews and
the weekly Workshop collection review. It does not copy policy into code,
change Workshop mode, or start another model review.

This is a model-governance adapter, not a filesystem ACL. Git history, Workshop
proposal records, ordinary tool policy, and operator review remain the recovery
and audit boundaries. With `autoCommitProvenance` enabled, the adapter blocks a
dirty or concurrently owned Workshop tree and commits each successful targeted
direct-auto review with `Change-Origin: workshop-autonomous`.

## Registry layouts

Without a registry override, the adapter discovers either layout:

1. combined `references/workspace-skill-registry.json`;
2. otherwise the split pair `references/authoring-ownership.json` and
   `references/repository-publication.json`.

An explicit `governanceReferencePaths` array wins. The compatibility shortcut
`workspaceSkillRegistryPath` selects one combined registry when the array is
absent. Missing, malformed, or unsupported combined registry data is labeled in
the injected context with an owner-only fallback; the adapter never invents a
grant.

## Install from this skill

Installation, config mutation, activation, reload, and restart require the
operator's authority. Publishing or copying this skill does not grant it.

1. Install this lifecycle skill in the agent's canonical workspace.
2. Customize its governance registry. Keep the default owner singular and link
   collaborator channels to durable Gateway profiles or trusted principals.
3. Set the plugin directory to this bundle's vendored copy and validate it:

   ```sh
   plugin_dir="/absolute/path/to/workspace/skills/openclaw-skill-plugin-lifecycle/assets/workshop-governance-plugin"
   cd "$plugin_dir"
   npm test
   npm pack --dry-run
   openclaw plugins install --link --force .
   ```

   A reviewed clone of the upstream repository is an equivalent installation
   source when an operator prefers a separate checkout.

4. Merge this shape into the existing config without replacing other plugin
   paths, allowlist entries, or plugin settings:

   ```json5
   {
     plugins: {
       load: {
         paths: [
           "/absolute/path/to/workspace/skills/openclaw-skill-plugin-lifecycle/assets/workshop-governance-plugin"
         ]
       },
       allow: ["workshop-governance-context"],
       entries: {
         "workshop-governance-context": {
           enabled: true,
           hooks: { allowConversationAccess: true },
           config: {
             lifecycleSkillPath:
               "skills/openclaw-skill-plugin-lifecycle/SKILL.md",
             autoCommitProvenance: true
           }
         }
       }
     }
   }
   ```

   Standard combined and split registries need no config path. Set
   `governanceReferencePaths` only for a nonstandard layout.

5. Run `openclaw config validate`, inspect the plugin with
   `openclaw plugins inspect workshop-governance-context --runtime --json`, and
   confirm three typed hooks with no diagnostics.
6. Apply with `openclaw plugins reload workshop-governance-context`, then
   inspect again. Restart only if reload cannot establish the cron baseline and
   the operator explicitly authorizes a restart.
7. Prove one bounded Workshop review contains
   `WORKSHOP_GOVERNANCE_CONTEXT_V2`, current lifecycle text, and the expected
   registry. A loaded-plugin receipt alone is not prompt-delivery proof.
8. Before enabling `auto`, prove a successful targeted review creates a clean
   provenance-bearing commit and prove recovery from that commit's Git history.

Keep Workshop in `propose` or `off` until the lifecycle skill's direct-auto Git
and recovery gates pass. The adapter does not make `auto` safe by itself.

## Maintain the bundled copy

After an upstream plugin change is tested, committed, and pushed, regenerate
this skill's copy from the clean checkout:

```sh
node scripts/workshop-governance-plugin-vendor.mjs sync
node scripts/workshop-governance-plugin-vendor.mjs check
```

The optional final argument selects another upstream checkout. Commit the
vendored tree and updated lock with the lifecycle skill. `verify` checks only
the bundled tree and lock, so downstream operators do not need the upstream
checkout.
